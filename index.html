El problemaThe problem

Cada instalación se diseñaba con lápiz sobre el plano impreso: medir ambientes, calcular la demanda, dimensionar radiadores o losa y contar materiales. Llevaba de 3 a 4 horas, y cada cambio obligaba a tachar o reimprimir, sin registro de versiones.

Every installation was designed in pencil on a printed plan: measuring rooms, calculating demand, sizing radiators or radiant floor, and counting materials. It took 3 to 4 hours, and every change meant crossing out or reprinting, with no version history.

Decisiones técnicasTechnical decisions

  • Valor calculado con corrección manual. Todo se calcula solo, pero el vendedor puede escribir otro valor encima: digitaliza el criterio de la empresa sin quitarle la última palabra al profesional.
  • Lógica separada de la interfaz. El cálculo no depende de React ni de Konva, y eso permite probar que da lo mismo que el método en papel.
  • Compartir sin exponer la tabla. El link usa un token y una función SECURITY DEFINER: nadie puede listar proyectos, solo abrir el suyo.
  • Sin servidor propio. PDF, planos y cálculo corren en el cliente; Supabase hace de backend.
  • Computed values with manual override. Everything is calculated automatically, but the salesperson can type a different value: it digitizes the company's method without taking the final say away from the professional.
  • Logic separated from the UI. The calculation does not depend on React or Konva, which makes it possible to test that it matches the paper method.
  • Sharing without exposing the table. The link uses a token and a SECURITY DEFINER function: nobody can list projects, only open their own.
  • No custom server. PDFs, plans and calculations run on the client; Supabase acts as the backend.

DesafíosChallenges

  • Geometría propia: Shoelace para áreas, recorte Sutherland-Hodgman, scanline para exclusiones, A* sobre grilla y simplificación Ramer-Douglas-Peucker.
  • Compatibilidad: funciones que migran formatos viejos para que los proyectos guardados no se rompan al actualizar.
  • Un bug que deshacía varias acciones juntas, resuelto con instantáneas completas por piso y pruebas que lo fijan.
  • Informes robustos: si una imagen tarda más de 8 segundos, el PDF se genera igual y avisa.
  • Custom geometry: Shoelace for areas, Sutherland-Hodgman clipping, scanline for exclusions, A* on a grid, and Ramer-Douglas-Peucker simplification.
  • Compatibility: functions that migrate old formats so saved projects do not break after updates.
  • A bug that undid several actions at once, fixed with full per-floor snapshots and tests that lock it down.
  • Robust reports: if an image takes longer than 8 seconds, the PDF is still generated with a warning.

El problemaThe problem

El mismo stock físico se vendía en dos canales sin un punto de consolidación. Saber qué unidad se fue por dónde exigía recontar todo. Además, el precio correcto en MercadoLibre depende de comisiones, cargos fijos, percepciones y envío, y calcularlo a mano no escala a 300 productos.

The same physical stock was sold on two channels with no single source of truth. Knowing which unit went where meant recounting everything. On top of that, the right MercadoLibre price depends on fees, fixed charges, tax withholdings and shipping, and calculating it by hand does not scale to 300 products.

Decisiones técnicasTechnical decisions

  • Webhooks que responden antes de trabajar. MercadoLibre desactiva un tópico si no recibe respuesta rápida; el handler confirma y procesa en una tarea aparte.
  • La unicidad vive en la base. Webhook y polling pueden procesar la misma orden a la vez; un índice único parcial lo resuelve donde la garantía es real.
  • Lock por usuario en el refresh del token. El refresh token de MercadoLibre es de un solo uso: dos refreshes simultáneos desconectaban la cuenta.
  • Pool de conexiones ajustado tras un error real de producción por el límite del pooler de Supabase.
  • Webhooks that acknowledge before working. MercadoLibre disables a topic if it does not get a fast response; the handler acknowledges and processes in a separate task.
  • Uniqueness lives in the database. Webhook and polling can process the same order at the same time; a partial unique index solves it where the guarantee is real.
  • Per-user lock on token refresh. MercadoLibre refresh tokens are single-use: two simultaneous refreshes disconnected the account.
  • Tuned connection pool after a real production error caused by the Supabase pooler limit.

DesafíosChallenges

  • Un precio que depende de sí mismo: la comisión incluye un cargo por tramo de precio, así que se resuelve iterando contra la API hasta converger a menos de $0,50.
  • El umbral de envío gratis, que obliga a decidir con una estimación previa para no inflar productos baratos.
  • Settlements donde una venta son varias filas, agrupadas por operación y clasificadas para revisión.
  • Deuda consciente: las migraciones son sentencias idempotentes en el arranque en lugar de Alembic, suficiente para una sola instancia.
  • A price that depends on itself: the fee includes a charge based on the price bracket, so it is solved by iterating against the API until it converges within $0.50.
  • The free-shipping threshold, which forces a decision based on a prior estimate so cheap products are not overpriced.
  • Settlements where one sale spans several rows, grouped by operation and classified for review.
  • Deliberate tech debt: migrations are idempotent statements at startup instead of Alembic, enough for a single instance.

El problemaThe problem

El servicio técnico se coordinaba por canales dispersos. Se perdían fechas de mantenimiento, el préstamo de herramientas no tenía seguimiento y la productividad de cada técnico era un dato que no existía.

Technical service was coordinated across scattered channels. Maintenance dates were missed, tool loans were not tracked, and nobody knew how productive each technician was.

Decisiones técnicasTechnical decisions

  • Puntajes calculados en la base de datos con triggers PL/pgSQL, para que no se puedan alterar desde el navegador.
  • Turnos validados con RLS cruzando el usuario con el turno activo, para evitar registros duplicados por clics simultáneos.
  • Plazos en días hábiles, porque las demoras de proveedores se miden al ritmo comercial.
  • Scores calculated in the database with PL/pgSQL triggers, so they cannot be altered from the browser.
  • Shifts validated with RLS by matching the user against the active shift, to prevent duplicate records from simultaneous clicks.
  • Deadlines in business days, because supplier delays are measured at a business pace.

DesafíosChallenges

  • Datos históricos en texto libre: técnicos cargados con nombres escritos a mano, normalizados para que las métricas cierren.
  • Recepción parcial con trazabilidad: el estado del pedido se deriva del estado de cada ítem.
  • Un ranking justo, que combina tasa de cumplimiento, tiempo de resolución y experiencia acumulada.
  • Historical free-text data: technicians entered with hand-typed names, normalized so the metrics add up.
  • Partial receipt with traceability: the order status is derived from the status of each item.
  • A fair ranking that combines completion rate, resolution time and accumulated experience.

Decisiones técnicasTechnical decisions

03 — Proceso03 — Process

Cómo trabajo con IAHow I work with AI

Claude Code es mi herramienta central de desarrollo. El agente escribe código; las decisiones, la revisión y la verificación son mías.

Claude Code is my core development tool. The agent writes code; the decisions, the review and the verification are mine.

01

Planificar antes de pedirPlan before prompting

Cada tarea arranca con un plan: qué cambia, qué no se toca y cómo se va a verificar. El prompt lleva el contexto del negocio, las restricciones y los criterios de aceptación, para que nada quede librado a la interpretación del agente.

Every task starts with a plan: what changes, what stays untouched and how it will be verified. The prompt carries the business context, the constraints and the acceptance criteria, so nothing is left to the agent's interpretation.

02

Tareas cortas, contexto persistenteShort tasks, persistent context

Divido el trabajo en tareas chicas y acotadas. Las decisiones, convenciones y hallazgos de cada sesión quedan en una memoria persistente (Engram), y la sesión siguiente arranca con el contexto correcto sin cargarlo de nuevo.

I split work into small, well-scoped tasks. The decisions, conventions and findings from each session go into a persistent memory (Engram), so the next session starts with the right context without reloading it.

Claude Code · Engram (MCP)

03

Revisar cada cambioReview every change

Leo cada diff antes de aceptarlo. Si el agente se sale del alcance, toma un atajo o da algo por hecho sin comprobarlo, lo freno en la revisión.

I read every diff before accepting it. If the agent goes out of scope, takes a shortcut or assumes something it has not checked, I stop it at review.

04

Verificar, no suponerVerify, don't assume

Un cambio no está terminado porque compila. Lo verifico con pruebas automatizadas, como los 102 tests de Warma, y en la aplicación funcionando.

A change is not done because it compiles. I verify it with automated tests, like Warma's 102, and in the running app.

Vitest · pytest
